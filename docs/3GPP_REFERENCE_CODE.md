# 3GPP specifications, reference code and test data

The 3GPP specifications of the three 256-bit algorithm sets contain informative reference
code in an annex, and separate documents contain the official test data. 3GPP holds the
copyright of these documents. **This package does not contain any of them.** All our code
is written from the normative text of the specifications.

## Documents used

| Set | Specification (normative text, annex code) | Implementers' test data |
|---|---|---|
| AES-256 (256-NEA5/NIA5/NCA5) | TS 35.243 V20.0.0 (`35243-k00.docx`), Annex B | TS 35.244 V20.0.0 (`35244-k00.docx`) |
| Snow 5G (256-NEA4/NIA4/NCA4) | TS 35.240 V20.1.0 (`35240-k10.docx`), Annex B | TS 35.241 V20.0.0 (`35241-k00.docx`) |
| ZUC-256 (256-NEA6/NIA6/NCA6) | TS 35.246 V20.0.0 (`35246-k00.docx`), Annex A | TS 35.247 V20.0.0 (`35247-k00.docx`) |

The documents are free to download from the 3GPP specification archive
(https://www.3gpp.org/ftp/Specs/archive/35_series/).

## Running the checks that need them

Put the six `.docx` files in one folder and run, from `code/`:

```
sudo apt install pandoc python3-cryptography
make verify DOCS=path/to/folder
```

This runs, for each set:

1. `test_official.py`: reads the test data from the `.docx` file and checks our L1 code
   against every official test (9 for the AES-256 set, 12 each for Snow 5G and ZUC-256).
2. `crosscheck`: extracts the annex reference code from your copy of the specification
   with `code/common/extract_annexb.py` into a local file (`annex_ref.cpp` or
   `annexb_35243.cpp`), compiles it next to our code and compares both on 5000 random
   full-mode inputs per algorithm.
3. On x86-64 or aarch64, the L2 and L3 equivalence tests.

The extracted annex files are build products. Do not commit them; `.gitignore` excludes
them.

## Checks that run without the 3GPP documents

- `make -C common check`: AES-256 (FIPS 197) and POLYVAL (RFC 8452) test vectors.
- `make -C l2x86 check`, `make -C l3x86 check`, `make -C l2arm check`: L2 and L3 against
  L1 on 20000 random inputs per algorithm.
- The ESP32 self-tests: L1 against digests of the PC outputs (`code/esp32/main/golden.h`),
  and L2 and HW against L1.
- The FPGA testbenches and the board test: vectors generated by the verified L1 code
  (`code/fpga/tb/vectors`).
